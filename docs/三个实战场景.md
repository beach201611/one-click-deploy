# 三个实战场景：从一句话到交付物

看不懂理论没关系，照下面三个场景走一遍，就会用了。每一步都写了**你该说什么**。

---

## 场景一：把一堆表格做成一份带图表的报告

**背景**：手里有 12 个月的销售明细，领导要一份季度汇总。

### 第 1 轮：先摸清情况

```
我要把附件里 12 个月的销售明细汇总成季度报告。
先帮我看看这批数据的结构，有哪些字段、有没有缺失和异常，
看完再告诉你怎么做比较合适，先不要动手生成文件。
```

> 用 Ask 或 Plan 模式起手，先让它汇报数据情况。这一步能省掉后面大量返工。

### 第 2 轮：正式下需求

```
按刚才的结论做：
1. 合并 12 张表成一张总表
2. 按季度和产品两个维度汇总销售额
3. 生成一份 Excel，含总表、汇总表、2 张图表
4. 再写一页文字结论，指出增长最快的产品和下滑最明显的区域
约束：原始文件不要动，金额保留两位小数，异常值单独列出来不要直接剔除。
```

### 第 3 轮：微调

```
图表配色换成蓝色系，另外把"合计"行加粗。
```

**要点**：三轮下来始终在同一个任务里。每轮只改一点，比一次说完 20 条要求更容易达成。

## 场景二：把会议记录做成 PPT

**背景**：开了两小时的会，录音转写稿 8000 字，明天要给老板汇报。

### 第 1 轮

```
附件是会议转写稿。先帮我提炼：这场会达成了哪几个结论，
有哪些待办、分别归谁，还有哪些问题没解决。用表格给我看。
```

### 第 2 轮

```
根据上面的结论做一份汇报 PPT，12 页左右，面向管理层。
结构：背景 → 三个核心结论 → 待办与时间表 → 风险与待决策 → 结尾。
风格简洁商务，每页不超过 5 条要点。
```

### 第 3 轮（大概率需要）

```
第 4 页和第 7 页文字太多了，改成图示表达。另外封面加上汇报人 [张三] 和日期。
```

**要点**：让它先"读懂"再"产出"。跳过第 1 轮直接要 PPT，通常出来的是把原文切成 12 段的流水账。

## 场景三：做一个能打开看的网页

**背景**：想给新产品做个介绍页，不会写代码。

```
做一个产品介绍单页网站，产品是 [一款帮小店主管理库存的工具]。
要求：
- 首屏：大标题 + 一句话价值主张 + 一个行动按钮
- 中间：三个核心功能，每个配图标和一句话说明
- 底部：价格三档对比 + 联系表单
- 深色科技风，手机端也要好看
- 做完直接给我能打开预览的版本
```

它会在右侧「网页」页签里把页面跑起来，你可以直接点开看效果。不满意就继续说：

```
第二个功能块的位置换到第一个，标题字号再大一点，整体偏冷色调。
```

**要点**：网页类任务一定要说"要能打开预览"，否则它可能只给你源码。看到效果后再提修改，比描述半天准确得多。

## 场景四（附加）：整理本地文件，别让 AI 乱动手

**背景**：下载文件夹里堆了 300 个文件，想按类型归档。

```
D:\Downloads 里有大约 300 个文件，帮我按类型归档：文档、图片、压缩包、安装包、其他。
先输出一份"将要执行的操作清单"给我看，我确认后再动手。
约束：只移动不删除，重名文件自动加序号，不要碰任何子文件夹。
```

看到清单后确认，再说一句：

```
清单没问题，按这个执行。
```

**要点**：所有涉及批量改文件的活，都用"先给清单再执行"这个套路。这是新手最该养成的习惯。

---

## 三个场景的共同规律

| 阶段 | 做什么 | 为什么 |
| --- | --- | --- |
| 第 1 步 | 先让它读懂材料 | 避免它在错误理解上狂奔 |
| 第 2 步 | 一次说清目标、输入、输出、约束 | 减少来回扯皮 |
| 第 3 步 | 小步微调，不重开任务 | 上下文还在，改起来更准 |
| 全程 | 结果右侧核对，批量操作先看清单 | 出了问题能及时发现 |
